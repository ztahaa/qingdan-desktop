# 手机短信提醒配置

本版本实现的是桌面端定时检查和 HTTPS 中转协议。短信发送需自行开通短信服务商账号、签名和模板，并部署服务商适配中转服务；没有这些配置不会产生短信。本仓库不内置密钥，也不会将手机或任务发给开发者。

1. 在电脑设置用户环境变量 `QINGDAN_SMS_TOKEN`，值由自己的中转服务提供。不要把密钥提交到 GitHub。设置后完全退出并重新打开清单。
2. 打开应用设置，填写带国际区号的手机号，例如 `+8613800000000`，和中转服务的 HTTPS URL，启用短信服务并保存。
3. 编辑需要提醒的任务，设置截止日期时间并勾选“截止时短信提醒”。
4. 保持电脑和应用运行。程序每 30 秒处理一条到期提醒，已完成或在回收站的任务不发送；重新启动只补发过去 24 小时内到期的任务。多人多任务高可靠调度或关机后提醒需要常在线服务，当前本地应用不提供。
5. 设置窗口显示密钥是否已配置，以及中转接收/失败数量。中转接收不代表手机已送达，最终送达需查询短信服务商回执。

## 中转服务协议

请求：`POST <配置的 HTTPS URL>`，使用 `Authorization: Bearer <QINGDAN_SMS_TOKEN>`，`Content-Type: application/json`。

```json
{
  "idempotencyKey": "qingdan:任务ID:截止时间:手机号",
  "phone": "+8613800000000",
  "taskId": "任务ID",
  "title": "待办任务标题",
  "dueAt": "2026-10-19T10:00:00.000Z"
}
```

服务端必须验证 Bearer token，对 `idempotencyKey` 持久去重，将标题、截止时间映射到已经审核的短信模板，并仅在短信服务商确认受理或任务已可靠入队后返回 200/201/202/204。重复请求不得重复发短信。不能只用一个始终返回 200 的空接口代替发送实现。

客户端不跟随重定向，单次超时 15 秒，最多尝试三次，间隔约 60 秒、120 秒，结果保存在 SQLite。网络超时可能发生在短信实际已经受理后，因此去重必须在服务端完成；同一任务修改截止时间或手机号会产生新的提醒键。备份恢复保留已有发送记录，恢复更早备份时仍须依赖服务端去重。

不要把短信服务商密钥打包进 exe 或前端代码。服务商凭据仅存中转服务端，中转 token 通过电脑环境变量提供。此功能可能产生运营商或服务商短信费用。
